# Редактор коллажа — дизайн (v1)

Решения (30.09.2026): состав = база + загрузка картинок с обработкой + призраки и фон;
текст правится прямо на холсте; блок при перетаскивании прыгает по ячейкам;
запуск командой в терминале, браузер открывается сам.

## Части
- `editor.html` + `editor.css` + `editor.js` — интерфейс. Холст = настоящий `index.html` в iframe
  с настоящим `style.css`; редактор дорисовывает сетку, выделение, ручки. Экранные эффекты и
  анимации в режиме правки выключены инъекцией стиля.
- `tools/serve.py` — локальный сервер (Python stdlib, порт 8787): отдаёт папку сайта и API:
  `GET /api/state` (список img/, фоны, текущий фон), `POST /api/save` (пишет index.html, бэкап в
  tools/backups/), `POST /api/upload?type=&name=` (кладёт в src/<type>/, дописывает cutouts.txt,
  запускает process.sh), `POST /api/bg?name=` (перегоняет фон, меняет --bg-image в style.css).
- `tools/edit.sh` + fish-функция `forest` — поднять сервер и открыть редактор.

## Что редактор умеет писать
Только: `--c --r --dx --dy --tilt --delay` и классы `reveal glitch fx-*` у блоков сетки;
`--x --y --w --o` у призраков; содержимое текста; `src/alt` картинок; порядок в DOM.
Ничего другого (z-index, position, px-координаты) он записать не может — в этом весь смысл.

## Инварианты, которые он охраняет
1. Текстовые поля не перекрываются: `textFieldsOverlap()` в editor.js (TODO(human)) — при
   конфликте перемещение отклоняется с подсветкой.
2. Обёртки (.page .ghosts .stage) не трогаются вообще.
3. Сохранение заменяет только внутренности `<main class="stage">` и `<div class="ghosts">`,
   остальной файл байт в байт как был.

## Холст
- Колонки: 12, ширина = (W − 11·16)/12. Ряды: `getComputedStyle(stage).gridTemplateRows`.
- Позиция блока читается из геометрии (offsetLeft/offsetTop, без transform), не из парсинга.
- Drag тела → новая колонка/ряд под курсором, размах сохраняется. Ручки по краям → размах.
- Двойной клик по тексту → contenteditable; Enter = новый абзац, Ctrl+I = курсив.
- Призраки тянутся мышью, пишутся `--x/--y` в процентах от .page.
- Кнопка «телефон» сужает iframe до 400px — срабатывает наш же медиазапрос.
- Отмена/повтор: снимки innerHTML сцены и призраков, до 50 шагов.


## v2 (30.09.2026): проявка, текст, iframe, обрезка, библиотека, страницы, публикация
- **Проявка через класс `.dev` + переменные.** Фильтр с тождественными значениями всё равно создаёт stacking context,
  поэтому правило включается только классом, а редактор снимает его, когда все значения дефолтные. `.reveal` потерял кадр
  `to` и получил `fill-mode: backwards`: с `both` конечные `opacity:1; filter:none` перебивали бы проявку навсегда.
  Призрак: blend/opacity переехали с `img` на `.ghost`, иначе `.dev` перебивал `--o`. Зеркало только у медиа.
  Для текстовых блоков из шести режимов оставлены overlay и soft-light. Рамка выделения рисуется отдельным слоем.
- **Текст без blur-обработчика.** Кнопки панели гасят mousedown, правка заканчивается явно (Esc, клик мимо, другой блок,
  сохранение). Ссылка — inline-поле с сохранением Range. Список только в `.field` (`<ul>` внутри `<p>` рвёт блок).
  Цвета — классами, `normalize()` держит allow-list тегов и span-классов.
- **Embed** — `kind` раньше `field`, в TEXTLESS (dblclick правит только подпись); iframe в редакторе без pointer-events.
  `embedSrc()` — TODO(human): список хостов и правила преобразования ссылок.
- **Обрезка** — своя пиксельная математика по rect canvas; точки crop-относительные, при изменении рамки пересчитываются,
  вышедшие отбрасываются. Строки cutouts.txt читает/пишет только `_cutout_line/_write_cutout_line`, всё под RLock
  вместе с process.sh (иначе два reroll внахлёст теряют шаг seed — проверено).
- **Библиотека считается на сервере**: использования по всем *.html и style.css, тип по исходнику и расширению
  (вырезка = .png, фото = .jpg), курсоры скрыты, удаление только при 0 использований.
- **Страницы**: файл создаёт редактор (DOMParser над index.html), сервер лишь пишет. Общие блоки — только по `id`
  (чекбокс сам выдаёт `s-<kind>-<n>`), синхронизация в браузере при сохранении, без регулярных выражений на сервере.
  Бэкапы `<slug>__<время>`.
- **Публикация через REST API**, не CLI (гем не установлен): явный allow-list файлов, `upload_hash` перед `upload`,
  пачки по 20, ошибки API показываются как есть (плохой ключ = 403 invalid_auth).
- **Защита сервера**: POST только с `X-Editor: 1` (чужая вкладка не сможет дёрнуть delete/restore/push простым запросом),
  имена страниц и файлов — только basename по шаблону.


## v3 (30.09.2026): афиша вместо сетки, независимая колонка, настраиваемый холст
- **Принцип v1 «редактор не пишет пиксели» сознательно отменён.** Сетка 12 колонок делала три дела разом (позиции,
  рост рядов, порядок телефона) и не давала свободно двигать блоки. Теперь два независимых режима одного HTML:
  афиша (`--x/--y/--w` px, `position: absolute`) и колонка (`--m`, flex). Обёртки по-прежнему не трогаются:
  высота холста берётся из подвала в потоке (`margin-top: var(--y)`), а не из переменной на `.stage` (правило 2).
- **Ширина не зашита.** Живая страница без скриптов, `@media` не читает переменные → всё, что зависит от ширины,
  генерирует сервер в `layout.css` из `tools/site.json` (`poster`, `phone`). `style.css` описывает оба режима через
  `--l-pos/--l-w/--l-ft/--l-page`, `layout.css` в медиазапросах только переключает их (+ `.hide-m/.hide-d`).
  Пороги: колонка ниже ceil(.78·W)+16, ступени zoom .78/.85/.92 до ceil(W)+16 (16 = классическая полоса прокрутки,
  медиазапросы считают её). Без `@supports (zoom:1)` — колонка до самой афиши.
- **Холст редактора = poster + 16 px** по той же причине (иначе ступень zoom включилась бы прямо в редакторе);
  сверху `.page{zoom:1!important}`.
- **Правило 1 по прямоугольникам**: `overlaps()` на `getBoundingClientRect` с запасом 8 px с каждой стороны
  (16 = промежуток старой сетки; 12 отклоняло перенесённую раскладку), считается в `refresh()`, `save()` отказывает.
  Магнит: если прилипшая позиция сталкивается с полем, берётся сырая (иначе прилипание по y «вгоняло» в соседа).
- **Перенос** `migrate()`: старый grid-CSS временно инжектится в iframe, измеряются offset* (без transform) + `--dx/--dy`,
  k = W_афиши / W₀ (1368/1148), масштабируются x, y, w (у вырезок и штампов `--w` = ширина файла — не трогается).
  Идемпотентен, проверен по индексу в DOM ±0.5 px. Настоящий index.html перенесён копированием результата из тестовой
  копии (исходник совпадал байт в байт), бэкап в tools/backups.
- **Ловушка**: `function snap()` истории отмены перекрыла одноимённую функцию магнита (позднее объявление побеждает) —
  переименована в `magnetize`. Harness: события клавиатуры слать на `body` (у `document` нет `matches`).
- Проверено headless Firefox (harness t11 в scratchpad, 34 утверждения). `zoom` + blend только в Firefox (Chrome нет).
- **Стол и лист (та же дата, по просьбе пользователя видеть страницу как посетитель).** iframe = экран посетителя
  (`screen`×`screenh` из site.json, не уже poster+16) и высотой во всю страницу (`page.offsetTop + offsetHeight`);
  масштаб — `transform: scale()` на iframe, размеры обёртки `#sheet` заданы явно, чтобы стол прокручивался.
  События внутри трансформированного iframe приходят в его координатах — drag/магнит о зуме не знают; пересчёт только
  на границе: панель текста, центр видимой области при добавлении блока, якорь Ctrl+колеса (источник события —
  по `e.target.ownerDocument`, не по `e.view`: у синтетических событий он пустой). `.bg` в режиме правки —
  absolute, `background-size: 100% auto; repeat-y` (fixed+cover на листе высотой 3000 раздул бы фон в 3 раза).
  Пометки: `.ed-margin` ×2 (поля вне `.page`), `.ed-fold` (первый экран), `.ed-label`. Панорама пробелом/средней
  кнопкой по `screenX/Y` (общие для окна и iframe). `overflow-anchor: none` на столе.
